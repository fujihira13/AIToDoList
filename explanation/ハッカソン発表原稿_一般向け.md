## スライド3：ソリューション紹介（40秒）

### スライド内容
```
💡 Eisenhower Board の考え方

仕事を「大事さ」と「急ぎ具合」で4つに分ける

┌──────────────────┬──────────────────┐
│  🔥 大事 × 急ぎ    │  🧠 大事 × 急ぎじゃない │
│  → 今すぐやる！    │  → 計画を立ててやる    │
├──────────────────┼──────────────────┤
│  ⚠️ 大事じゃない × 急ぎ │  🌿 大事じゃない × 急ぎじゃない │
│  → 誰かにお願いする  │  → やらなくてもいいかも  │
└──────────────────┴──────────────────┘

✨ さらに！担当者の表情が状況に合わせて変わる！
```

### 発表文言
> 「このアプリは、仕事を『大事かどうか』と『急ぎかどうか』の
> 2つの軸で、4つのグループに分けて管理します。
> 
> 例えば、大事で急ぎの仕事は『今すぐやる』。
> 大事だけど急ぎじゃない仕事は『計画を立ててやる』。
> 大事じゃないけど急ぎの仕事は『誰かにお願いする』。
> 大事でも急ぎでもない仕事は『やらなくてもいいかも』。
> 
> これだけなら普通のタスク管理なんですが...
> 
> このアプリのすごいところは、
> 仕事の状況に合わせて、担当者の顔写真の表情が変わるんです！
> 
> 急ぎの仕事を抱えている人は怒った顔に、
> 余裕がある人はにっこり笑った顔になります。」

## 🎤 一般向け発表のポイント

### 避けるべき専門用語

| ❌ 専門用語 | ✅ 言い換え |
|------------|-------------|
| API | 裏側の仕組み |
| フロントエンド | 画面 |
| バックエンド | サーバー、裏側 |
| データベース | データの保存場所 |
| ドラッグ＆ドロップ | マウスで掴んで移動 |
| レンダリング | 画面の表示 |
| JSON | データ |
| モジュール | 部品 |
| フレームワーク | 土台となる仕組み |

### 話し方のコツ

1. **例え話を使う** - 「付箋をホワイトボードに貼るような感覚です」
2. **身近なものに例える** - 「LINEを使うような感覚で使えます」
3. **メリットを強調** - 「これで○○できるようになります」
4. **デモを多めに** - 言葉で説明するより見せた方が伝わる

### よくある質問への回答例

**Q: 難しそうですが、使いこなせますか？**
> 「ネットショッピングができる方なら大丈夫です。
> 仕事を追加して、完了したらチェックするだけです。」

**Q: 無料で使えますか？**
> 「今は開発中なので無料でお試しいただけます。
> 正式リリース時の料金は検討中です。」

**Q: スマホでも使えますか？**
> 「現在はパソコン向けに作っていますが、
> スマホ対応も計画しています。」
